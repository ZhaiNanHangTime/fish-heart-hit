# fish-heart-hit · 心率直播叠层

把蓝牙心率实时叠到直播画面上：一条红线横穿、一只会突刺的像素角色、一个大号心率数字。
颜色**如实反映强度**，额外的动画负责**节目效果** —— 两者分开，不靠伪造心率。

> 中文叫「咸鱼突刺」：一只背矛的像素咸鱼，心率越高突刺越猛。

数据源是标准 BLE 心率广播（GATT `0x180D` / `0x2A37`），任何支持心率广播的手环/胸带都能用，
**不绑定任何具体设备**：不指定 `--address` 时会自动扫描。

内置两套像素皮肤，网页与桌面悬浮窗共用同一套算法：

| 皮肤 | 角色 | 说明 |
|---|---|---|
| `fish`（默认） | 背矛咸鱼 | 心率越高突刺越猛，出满红时矛头/令旗发亮 |
| `ghost` | 幽灵 | 飘浮上下浮动，爆发时窜得更明显；冷静偏冷白、激动转暖红 |

## 一、安装

```bash
git clone https://github.com/<你的用户名>/heart-rate-live-hud.git
cd heart-rate-live-hud
pip install -r requirements.txt
```

依赖只有两个：`bleak`（BLE 读取）、`aiohttp`（本地 Web 服务）。

**准备手环**：手环 → 设置 → **心率广播**（或进「锻炼」开始一个运动），保持亮屏。
手环退出广播后画面显示 `---` 并转红点，**不用重启服务**，重新开广播会自动接回。

## 二、启动

```bash
python heartrate_live.py                                # 自动找心率设备（见下方说明）
python heartrate_live.py --name Amazfit                 # 多台 BLE 设备时按名字找
python heartrate_live.py --address AA:BB:CC:DD:EE:FF    # 直接指定设备（最可靠）
```

### 自动找设备：能力与边界（实测结论，别踩坑）

找设备按这个顺序来，命中即停：

| 顺序 | 做法 | 速度 |
|---|---|---|
| 0 | 直连 `devices.json` 里上次成功过的地址 | 秒级 |
| 1 | 广播包里直接声明了心率服务 `0x180D` 的设备 | 一轮 8 秒 |
| 2 | 对信号最强的几台依次**连上去读 GATT 服务表** | 每台约 8 秒 |

**为什么需要第 2 步**：实测手环（华为、Amazfit）**广播包里根本不含 `0x180D`**，
Amazfit Pop Pro 广播里只有厂商私有服务 `0xFEE0`。所以"从广播 UUID 里认心率设备"这条路
在真机上不成立，必须连上去问 GATT。

**已知边界**：被测的这块手环**只在有限时间窗内广播**（实测：连续扫描 20 秒、
服务停机后再扫 8 秒，都从未出现在扫描结果里，即使服务正连着它）。
对这种设备：

- 首次启动时若扫不到，程序默认重试 **3 轮**（`--scan-attempts` 可调大），
  期间可以唤醒手环 / 重新开一次「心率广播」；
- 最省事的做法是**手动指定一次** `--address`；连上后地址会写进 `devices.json`，
  之后启动先直连它（秒级），只有连不上才去扫描；
- 换设备或想重新扫描：删掉 `devices.json`，或 `python heartrate_live.py --forget`。

Windows 双击即用的入口：

| 文件 | 作用 |
|---|---|
| `start-heartrate-gui.bat` | **图形控制台**（看心率 / 启停服务 / 校准基准 / 调参 / 开各页面） |
| `start-heartrate.bat` | 服务 + 桌面悬浮窗（直播叠加用） |
| `start-heartrate-live.bat` | 只启服务 |
| `stop-heartrate.bat` | 全部停止 |

## 五、算法（冻结版）

### 颜色通道：诚实

```
B   = 个人基准，开播头 3 分钟锁定后不再漂移（或点控制台「校准基准」手动锁定）
P90 = 最近 10 分钟第 90 百分位心率
R   = clamp(P90 − p90Offset,  B + minGap,  B + maxGap)   ← 满红阈值，15 秒时间常数缓慢跟随

白 = B     黄 = B + (R−B)×0.4     橙 = B + (R−B)×0.7     红 = R
```

- 用 **P90** 而不是最大值：反映"最近的强度水平"，不被一次偶发尖峰锁死
- `B + minGap` = **防假红**；`B + maxGap` = **防抗红**
- **B 必须在开播时锁定**：实测中用过"全场累计 min/avg"当基准，结果开播初期样本少、min 偏高
  → B 偏高 → R 被顶到 114，而本人峰值只有 104，**永远差一口气红不了**
- 强度走 **Attack(2s) / Release(6s)**：上色快、褪色慢，画面不闪

### 特效通道：节目效果（与颜色完全独立）

```
30 秒内上涨 ≥ burstRise(10) bpm，且当前 ≥ B + burstAbove(15)
→ 触发约 1 秒的"心跳爆发"：数字提亮 + 像素角色猛突刺 / 幽灵猛窜
冷却 burstCooldown(30) 秒
```

**即使心率绝对值不高，突发紧张也有反馈**，而且不会污染颜色通道。

### 四个保护

| 保护 | 做法 |
|---|---|
| 传感器误差 | **不做滤波**（主流心率广播设备读数可靠，避免引入延迟） |
| 颜色抖动 | Attack / Release 双时间常数 |
| 满红误触发 | 连续达阈值 `redHold`(2s) 才算满红，回落 `redDrop`(5) 解除（迟滞） |
| 数据断开 | 超过 `offlineAfter`(5s) 没新数据 → 显示 `---` + 红点，不沿用旧值 |

### 时间常量速查

| 常量 | 值 | 为什么 |
|---|---|---|
| B 冷却期 | 3 分钟 | 开播初期样本少，过早锁基准会把 B 锁高 |
| R 跟随时间常数 | 15 s | 够慢，不会因一两次读数抖动脉冲式变红 |
| Attack / Release | 2 s / 6 s | 上色快、褪色慢 → 有"冲上去"的观感又不闪 |
| 满红迟滞 | 2 s 进 / 5 bpm 出 | 防止在阈值上下反复横跳 |

## 六、参数怎么调

**方式一（推荐）**：图形控制台 → 拖滑杆 → 「保存参数」
**方式二**：打开 `http://127.0.0.1:8080/tune` → 拖滑杆看实时预览 → 「保存到服务端」
**方式三**：`/tune` 里「复制参数」拿到 `?minGap=22&...`，贴到 OBS 浏览器源地址后面（URL 参数优先级最高）

| 参数 | 默认 | 作用 |
|---|---|---|
| `skin` | `fish` | 皮肤：`fish` / `ghost` |
| `minGap` | **22** | R 至少比基准高多少（**调小 → 更容易红**，但可能假红） |
| `maxGap` | **30** | R 最多比基准高多少（防抗红；曾用 45，实测让 R 顶到 114） |
| `p90Offset` | 3 | R = P90 − 该值 |
| `anchorTau` | 15 | 阈值跟随速度（秒） |
| `attack` / `release` | 2 / 6 | 上色 / 褪色时间常数（秒） |
| `redHold` / `redDrop` | 2 / 5 | 满红迟滞 |
| `offlineAfter` | 5 | 多久没数据算离线（秒） |
| `burstRise` | 10 | 窗口内涨多少触发特效 |
| `burstAbove` | 15 | 且要高于基准多少 |
| `burstWindow` | 30 | 涨幅观察窗口（秒） |
| `burstCooldown` | 30 | 特效冷却（秒） |

## 七、用真实记录验收

控制台网页里**点一行记录**就能回放（走 `/replay` 接口）；命令行等价于：

```bash
python replay_check.py logs/heart-rate-YYYYmmdd-HHMMSS.csv   # 三个指标
python tune_scan.py    logs/heart-rate-YYYYmmdd-HHMMSS.csv   # 参数扫描对比
```

输出：
- **节目效果**：满红次数、突发特效次数（换算成"每 10 分钟几次"）
- **真实性**：平静期假红次数
- **稳定性**：阈值最大跳变、R 的波动范围
- **阈值诊断**：有多少个采样点站在阈值之上、最长连续多久（判断"是不是差一口气"）

**实测判读**：

| 结果 | 怎么办 |
|---|---|
| 满红 0~0.5 次/10min | 不够刺激 → `minGap` 降到 18~20 |
| 满红 1~2 次/10min + 假红 0 | 冻结这套参数 |
| 出现平静期假红 | 提高 `minGap`，或把 `redHold` 调到 3~4 秒 |
| 阈值诊断显示"最长连续 0.0 秒" | 说明峰值根本没碰到阈值 → 查 B 是否锁高了 |

## 八、皮肤怎么加

两套皮肤各有一份像素网格，网页与桌面悬浮窗各存一份（暂未共享）：

| 位置 | 内容 |
|---|---|
| `web/pixel.html` | `GHOST_ROWS` 网格 + `pixelShape()` 通用绘制（`.` 透明 · `#` 身体 · `E` 眼睛 · `T` 舌头） |
| `heartrate_hud.py` | `GHOST_ROWS` 网格 + `_draw_ghost_only()` |

改网格字符串就能改形状；`pixelShape()` 会**只在邻居透明的一侧描边**，所以轮廓是自动生成的。

> **踩坑记录（改悬浮窗绘制前必读）**：tkinter 画像素有两处"差一像素"的坑，桌面版都踩过：
>
> 1. **矩形的右下边界是开区间**：`coords(x, y, x+w, y+h)` 实际只覆盖 `w-1` 个像素。
>    用"每格描边块 + 填充块"的画法时，相邻格的描边会在格缝处叠成 2px 暗带，
>    正好落在填充之外 → 每个格子被暗线围住，整个幽灵变成**网格颗粒感**；
>    眼睛、舌头这类 1 格宽的部件还会被画成 2 格。
> 2. **非整数坐标会触发取整跳变**：实测飘浮偏移小数部分 = `.25` 的帧，身体像素数
>    从 1439 突增到 1864。幽灵飘浮每帧只变亚像素小数，于是周期性触发 → **一闪一闪**。
>
> 现在桌面版的写法是：
> * 用 `_pix_rect()` 这个"像素区间原语"（内部把坐标写成 `[x-0.5, x+size-0.5]`），
>   保证精确铺 `size` 个像素，相邻块严丝合缝；
> * 填充先铺实心，轮廓条只在"朝空白的一侧"画 —— 与网页版 `pixelShape()` 同思路；
> * 飘浮量用 `_quantize_unit()` 量化到 1px 台阶。
>
> 修复后：走满一个心跳周期 40 帧，身体像素数极差 = 0（scale 4 与 3 均为 0），
> 位移严格 1px 台阶。改这块代码请保持这两个不变量。

## 十、常见问题

**画面显示 `---`**
手环退出广播了 → 重新开启；或服务没启动 → 开图形控制台点「启动心率服务」。

**自动扫描找不到设备**
先确认手环在广播、屏幕亮着；然后看日志停在 "第 n/N 轮" 还是 "没有心率服务，跳过"：
- 卡在"没有设备在广播里声明 0x180D"是**正常**的（多数手环都这样），它会退到 GATT 探测；
- 探测了一堆陌生设备都没有心率服务 → 说明手环此刻不在广播。
最省事就是**手动指定一次** `--address`，之后地址会被记住（`devices.json`），启动先直连。

**一直不满红**
先看控制台的锚点行：如果 `10分P90` 远低于 `基准 + minGap`，说明这段确实没到强度 → 调小 `minGap`。
如果**基准 B 明显高于你的平静心率**，点「校准基准」重锁。

**颜色一闪一闪**
调大 `release`（褪色更慢）或 `redHold`（满红迟滞）。

**改了参数没生效**
要「保存参数」，且**网页需刷新**、**悬浮窗需重启**才读取新值。

**换了皮肤，悬浮窗没变**
悬浮窗每 2 秒跟服务端 `skin` 对一次，变了会自己重启生效；也可以右键菜单直接切。

**悬浮窗不见了**
删掉 `hud.json` 再启动，会回到屏幕右上角。

## 十一、已知可改进项

- `web/pixel.html` 的 `pixelShape()` 里描边取色写成 `colors.line`，而传入的键是 `line`（无点号），
  因此**网页版幽灵目前没有描边**（桌面悬浮窗版是正常的）。修法：把 `colors.line` 改成 `colors['line']`。
- 两套皮肤都要求启动时能连上服务拉取 `/params`；服务没起来时按内置默认值（`fish`）渲染。
